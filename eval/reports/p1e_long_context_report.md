# P1-E Long-context 与 RAG 对照实验报告

日期：2026-08-20。P1-E 的问题不是“上下文越长是否一定越好”，而是在同一份 E5 Docling 结构化 Block 上，比较不同上下文选择方式的引用覆盖、拒答、Token 与延迟。

## 1. 实验协议

所有模式均固定使用 `docling 2.120.2 + structure_aware_v1` 生成的 E5 Block，模型、Prompt、最大输出 Token、温度及引用 JSON 格式保持一致。只有上下文选择策略不同：

| 模式 | 上下文选择 | 检索链路 |
|---|---|---|
| LC1 | 当前单篇论文全部 Block | 无检索 |
| LC2 | 两篇相关论文全部 Block | 无检索 |
| N0 | E5 Block 的 Dense Top-K | Dense |
| A0 | E5 Block 的候选上下文 | Dense + BM25 + RRF + BGE Reranker |

引用 Precision / Recall / F1 只检查“论文键正确且页码与 Gold 证据区间重叠”，不把它误称为答案语义正确率。答案语义仅对 Dev 的代表性样本进行人工复核；没有用另一个 LLM 伪造 Test 的答案正确性分数。

| LC2 | 跨论文 | 10 | 0.5708 | 0.8750 | 0.6786 | 0.5000 | 45,802 | 3,637.61 ms |

人工复核材料与结论：

- [LC1 / LC2 / N0 的 20 条复核](../../docs/p1e_dev_answer_review.md)：单论文样本中 LC1 为 5 条正确，N0 为 2 条正确、3 条不正确；跨论文样本中 LC2 为 3 条正确、2 条部分正确，N0 为 3 条正确、1 条部分正确、1 条不正确。
- [A0 的 10 条复核](../../docs/p1e_a0_dev_spot_review.md)：单论文为 2 条正确、1 条部分正确、2 条不正确；跨论文为 3 条正确、1 条部分正确、1 条不正确。
- 这些样本是用于定位错误类型的有目的抽样，不能外推为总体语义正确率。典型错误包括：局部实验设置漏召回、跨论文 residual evidence 漏召回、无根据的细节补充，以及正文已经拒绝但 JSON 的 `refused` 字段未正确置位。

## 3. 冻结后的 Test 结果

Test 在配置冻结后才执行；不根据下表改动任何参数。单论文 Test 共 24 题（其中 4 条不可回答），跨论文 Test 共 5 题（其中 1 条不可回答）。

| 模式 | 数据 | 实际调用题数 | Citation P | Citation R | Citation F1 | 正确拒答率 | 平均 Prompt Token | P50 端到端延迟 |
|---|---|---:|---:|---:|---:|---:|---:|---:|
| LC1 | 单论文 | 24 | 0.8383 | 1.0000 | 0.8975 | 0.5000 | 36,617 | 3,070.57 ms |
| N0 | 单论文 | 24 | 0.3917 | 0.5250 | 0.4383 | 0.5000 | 2,181 | 1,935.64 ms |
| A0 | 单论文 | 24 | 0.5750 | 0.7000 | 0.6067 | 0.5000 | 2,618 | 4,487.02 ms |
| LC2 | 跨论文 | 0 | — | — | — | — | — | — |
| N0 | 跨论文 | 5 | 0.0833 | 0.1250 | 0.1000 | 0.0000 | 2,368 | 2,628.44 ms |
| A0 | 跨论文 | 5 | 0.2292 | 0.3750 | 0.2833 | 0.0000 | 2,557 | 6,007.50 ms |

LC2 的 5 条跨论文 Test 没有调用模型。运行器在调用前发现 `CD011`（SAM 与 SimCLR）需要 895 个 Block、预估 107,700 Prompt Token，超过冻结的 96,000 上限；为保证同一配置下的全量比较不发生悄悄截断，运行器按 all-or-nothing 规则拒绝整组。该 dry-run 记录保存在忽略的本地运行目录中。没有通过临时调大上限、截断文档或只运行其余 4 条来制造一个不可比的 LC2 Test 分数。

## 4. 结论

1. **单论文全文上下文确实有强引用覆盖，但代价高。** LC1 的 Test Citation F1 为 0.8975，明显高于 A0 的 0.6067；但平均 Prompt Token 为 36,617，约为 A0 的 14 倍。因此 LC1 更适合作为“全文精读 / 综述”显式模式，不适合作为默认问答路径。
2. **A0 在单论文 Test 中优于 Naive Dense RAG。** A0 的 Citation F1 从 N0 的 0.4383 提升至 0.6067，Recall 从 0.5250 提升到 0.7000；代价是平均输入 Token 增加约 20%，且本地检索和重排让端到端 P50 更长。这个结论只描述本数据集上的回答引用表现，不替代 P1-C 的独立检索消融结论。
3. **跨论文仍是主要短板。** A0 虽将跨论文 Test Citation F1 从 0.1000 提升到 0.2833，但两个 RAG 模式在唯一不可回答题上的正确拒答率均为 0。论文来源配额、跨论文证据覆盖与拒答校准尚未解决。
4. **LC2 的失败是结果，而不是漏做。** 两篇全文 Block 在 `CD011` 上超过 96k 上限，表明“把多篇论文全文直接塞给模型”无法稳定扩展。它同时会推高成本，并使来源混淆更难控制。
5. **不能仅凭延迟表解释系统快慢。** LC1 没有本地检索/重排而 A0 有，且网络和模型服务波动未被重复实验消除；P50/P95 仅作为本机本次运行记录，不作普适性能宣称。

## 5. 产品选择与后续工作

- 保持 E5 Advanced Retrieval（A0）为当前 ResearchPilot 的高精度默认检索链路；N0 保留为快速、低成本对照；LC1 作为用户显式选择的“单论文全文阅读”模式。
- 不把 LC2 做成产品默认能力。下一阶段先实现**论文级均衡候选配额、来源约束引用和拒答阈值校准**，再重新设计跨论文上下文实验。
- 因为 Test 题由项目作者编写，虽然 Test 使用了 Dev 未参与调参的留出论文，也仍不是完全盲测。今后应引入第二位标注者或论文级新语料进行外部复核。
- 真实账单成本未写入报告：配置没有硬编码会随供应商变化的单价，运行记录保留了 Prompt / Completion Token 与调用次数，可用于在 DeepSeek 控制台核对实际费用。

## 6. 可复现入口

聚合报告位于 `eval/results/*_answers.md`；逐题 JSONL 位于忽略的 `data/runtime/answer_evaluations/`。例如：

```powershell
.venv\Scripts\python.exe scripts\run_answer_eval.py `
  --config configs\experiments\a0_advanced_rag_e5.yaml `
  --dataset-kind single --split test --run
```

注意：Test 已冻结并实际运行；请不要再次执行该命令来调整参数。新的改进应创建新的实验配置和新的版本化评测协议。
