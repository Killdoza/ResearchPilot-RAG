# 跨论文评测集标注规范 v0.1

本规范用于 `ai_cs_crossdoc_v0.1`。它评估的不是“模型是否知道论文常识”，而是系统能否在多个给定论文中找对证据、区分来源，并在不具备可比条件时可靠拒答。

## 一题的最小结构

每题至少引用两篇论文，并在 Markdown 中填写：`split`、`task_type`、`answerable`、`paper_keys`、问题、预期答案、页级证据和标注备注。

- 可回答题：`task_type: cross_document`、`answerable: true`。把答案拆成 C1/C2/C3 等原子结论；每篇论文至少有一条页级证据，且每个结论均被至少一条证据覆盖。
- 不可回答题：`task_type: unanswerable`、`answerable: false`。不填写 C 结论或伪造页码；预期答案必须说明为何不能据给定论文作答，例如任务、数据集或指标不可直接比较。
- `paper_keys` 中的论文必须都在基础语料 Manifest 中，且同属 Dev 或同属 Test。禁止一题混合两侧论文。

## 证据与页码

`page_start/page_end` 使用 PDF 阅读器显示的物理页码，从 1 开始，而非论文印刷页码。证据应能直接支持关联的 C 结论；不能仅凭相关背景、模型常识或论文标题推断。

同一结论需要综合两篇论文时，可以让不同 Evidence 共用同一个 `claim_id`。但所有被引用的论文都必须在 `paper_keys` 内，且每篇论文至少有一条 Gold Evidence。

## 中英文与比较边界

问题可用中文，证据原文可为英文；`supporting_text_summary` 应用中文简洁说明“该页支持什么”，不复制大段论文原文。跨论文回答必须指出来源差异，不能把不同任务、指标或方法层级强行排成“谁更好”。

特别是以下情况应标为不可回答：

- 两篇论文没有在同一任务、同一数据集和同一指标下直接对比；
- 一个对象是模型架构、另一个是训练算法或安全攻击，论文没有提供可直接比较的结论；
- 所需实验、消融或实现细节没有出现在给定论文中。

## 划分与冻结纪律

- Dev（当前 10 题）只用于修改 Prompt、上下文上限和引用解析规则。
- Test（当前 5 题）只能在 P1-E 配置冻结后运行一次；不得根据 Test 结果继续调参。
- 运行前执行 `python scripts/validate_crossdoc_eval.py`。它验证 JSONL SHA-256、页码范围、论文键和论文级 Split 隔离。
- 如发现 Gold 页码或结论错误，先修改 Markdown、重新导入并提交新的数据集版本/哈希；不要悄悄改 JSONL 或覆盖已经报告过的 Test。
